## Why

用户现在用 diffview 看完 AI 的改动后，还得回到 VS Code 或终端去暂存、提交、推送。用户希望 diffview 直接提供 VS Code 源代码管理面板的那套操作和布局（参照 VS Code 1.117），看完改动就在同一个窗口里提交上传；同时每次启动都要重新选文件夹，希望像 VS Code 欢迎页一样列出最近打开过的项目。

这改变了项目原来的边界：第 1 期定位为「只读查看器，不做暂存/提交等写操作」（`openspec/config.yaml` 的 context 也这么写）。按 config 里「除非用户明确提出」的约定，这次用户明确要求了，所以本变更把 git 写操作纳入范围，并同步修改 config 的边界描述。

## What Changes

- **布局改成 VS Code 工作台样式**：左侧「SOURCE CONTROL」侧栏（标题栏上有提交、刷新、「…」更多操作按钮；提交信息输入框；带下拉菜单的「提交」按钮；「暂存的更改」「更改」分组文件列表）；右侧编辑区（标签页 + 路径面包屑 + 左右对照 diff，标签栏右侧有上一处/下一处改动、切换并排/内联按钮）；底部状态栏（分支名、待拉取/待推送提交数，点击同步）。
- **配色固定为 VS Code 默认的 Dark Modern 深色主题**，不跟随系统（VS Code 默认也不跟随）。
- **BREAKING（相对第 1 期规格）改动分两组展示**：「暂存的更改」= HEAD 与暂存区的差异，「更改」= 暂存区与工作区的差异（含未跟踪文件，状态字母 U）。第 1 期「同一文件暂存和未暂存的改动合并成一份相对 HEAD 的 diff」的规则作废。有冲突的文件单列「合并更改」组。
- **BREAKING 点击文件只打开这一个文件的 diff**（上一轮已实现，本次补进规格）：取代第 1 期「所有文件在一个连续视图里、点击跳转」的规则。
- **文件级操作**：暂存、取消暂存、放弃更改（未跟踪文件为删除，需二次确认）、用系统默认程序打开文件；分组标题上有「全部暂存」「全部取消暂存」「全部放弃」。
- **提交**：⌘Enter 或「提交」按钮提交暂存区；没有暂存任何文件时，按 VS Code 的默认行为先询问「是否暂存全部更改并直接提交」。下拉菜单提供「提交」「提交（修改上次提交）」「提交并推送」「提交并同步」。
- **远程**：拉取、推送、同步（先拉取再推送）、获取（fetch）；当前分支没有上游时，推送改为「发布分支」。认证完全依赖本机 git 已配置的凭据（SSH key、钥匙串），需要交互输入时直接报错说明，不在应用里弹登录框。
- **操作反馈**：git 写操作在后台执行，执行期间相关按钮不可用并显示进度；失败时弹出通知，附 git 的错误输出；完成后自动刷新。
- **欢迎页与最近项目**：未打开文件夹时显示欢迎页，「启动」区有「打开…」，「最近」区列出最近打开的仓库（文件夹名 + 用 `~` 缩写的上级目录），默认显示 10 个，「更多…」展开全部；点击即打开；路径已不存在时提示并可从列表移除。新增菜单项「关闭文件夹」回到欢迎页。

## 不做的事

- 克隆仓库、连接远程（欢迎页上 VS Code 的「克隆 Git 仓库…」「连接到…」不做）。
- 分支的创建、切换、合并、变基，标签管理，stash。
- 冲突解决界面：冲突文件只列出、可查看、可在终端解决后暂存，不提供「采用当前/传入」按钮。
- 按行或按块暂存（stage selected ranges）、在 diff 里编辑文件、提交历史图（Graph）、提交信息模板与 AI 生成提交信息。
- 应用内的 git 登录 / 凭据输入、自动定时 fetch（VS Code 的 `git.autofetch` 默认也是关闭的）。
- 左侧 VS Code 的活动栏（资源管理器、搜索、扩展等图标）：本应用只有源代码管理一个视图，不放无用的图标。
- 多标签页同时打开多个文件的 diff：编辑区只有一个标签，点击别的文件就替换它（相当于 VS Code 的预览标签）。
- 浅色主题、主题切换与设置界面；VS Code 那些「始终 / 从不」类的记忆选项。
- 菜单「打开最近」子菜单（最近项目只在欢迎页展示）。
- 提交历史与分支对比（原第 2 期）、语法高亮与文件监听（原第 3 期）仍在后续期，本变更不涉及。

## Capabilities

### New Capabilities

- `source-control`: 暂存 / 取消暂存 / 放弃更改、提交（含修改上次提交、无暂存时的确认）、拉取 / 推送 / 同步 / 获取 / 发布分支、分支与同步状态、写操作的执行与错误反馈。
- `workbench-layout`: VS Code 工作台式的整体布局（侧栏、编辑区标签页与面包屑、状态栏）和固定的 Dark Modern 深色配色。

### Modified Capabilities

- `open-repository`: 未打开文件夹时的空状态改为欢迎页；新增最近打开的项目列表和「关闭文件夹」。
- `worktree-diff`: 改动按「暂存的更改 / 更改 / 合并更改」分组，取消「暂存与未暂存合并展示」；列表项改为状态字母 + 文件名 + 目录的样式；点击文件只显示该文件的 diff（取代连续视图与跳转）；长行在每栏内裁切并同步横向滚动（取代「每栏宽度等于最长行」的组件默认行为）。

## Impact

- 代码：`src/git.rs` 增加状态读取与写操作命令；`src/repository_view.rs` 拆分为侧栏、编辑区、状态栏、欢迎页等模块；`src/main.rs` 增加菜单项、动作和主题初始化；新增最近项目的持久化模块。
- 依赖：新增 `serde`、`serde_json`（读写最近项目文件，已在锁文件中作为间接依赖）、`dirs`（取 `~/Library/Application Support`）。vendor 的 gpui-component 补丁可能需要小改（diff 行底色对齐 VS Code 配色时），改动同步到 `patches/`。
- 数据：在 `~/Library/Application Support/diffview/recent.json` 保存最近项目列表。
- 行为风险：应用第一次会修改用户仓库（暂存区、提交、远程），并会触发仓库的 git 钩子（pre-commit 等）和提交签名，这与 VS Code 一致。
- 文档：`openspec/config.yaml` 的项目边界描述、README 的功能说明、项目记忆需要同步更新。
