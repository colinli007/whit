## Purpose

按 VS Code 资源管理器的样式和交互，在侧栏以树形列出仓库里的文件和文件夹，并标出 git 状态，让用户可以浏览项目、打开任意文件查看或编辑。

## ADDED Requirements

### Requirement: 活动栏与侧栏视图

打开仓库后，窗口最左侧 SHALL 显示 VS Code 的活动栏：宽 48 像素，背景与侧栏相同，自上而下是「资源管理器」和「源代码管理」两个图标。点击图标 SHALL 把侧栏切换到对应视图，当前视图的图标 SHALL 高亮，并在左边缘显示一条竖线。「源代码管理」图标 SHALL 在有改动时显示改动文件总数的徽标。打开仓库后侧栏默认显示源代码管理。未打开仓库（欢迎页）时 SHALL 不显示活动栏。

#### Scenario: 切换到资源管理器

- **WHEN** 用户打开仓库后点击活动栏的「资源管理器」图标
- **THEN** 侧栏显示资源管理器，「资源管理器」图标高亮，「源代码管理」图标恢复为普通样式

#### Scenario: 改动数量徽标

- **WHEN** 仓库有 3 个改动文件，侧栏正在显示资源管理器
- **THEN** 「源代码管理」图标右下角显示徽标 `3`

#### Scenario: 欢迎页没有活动栏

- **WHEN** 未打开任何仓库
- **THEN** 窗口不显示活动栏

### Requirement: 资源管理器的结构

资源管理器自上而下 SHALL 包含：标题行（文字「EXPLORER」），以及以仓库文件夹名（大写）为标题的可折叠区域。区域内以树形列出仓库根目录的内容。每行高 22 像素，依次显示：每层 8 像素的缩进，以及层级参考线、文件夹的展开/折叠箭头、图标、名称。文件图标与源代码管理侧栏使用同一套图标。鼠标悬停在区域标题上时 SHALL 显示「全部折叠」按钮，点击后折叠所有已展开的文件夹。

#### Scenario: 根目录内容

- **WHEN** 仓库根目录有 `src/`、`Cargo.toml`、`README.md`
- **THEN** 区域标题是仓库文件夹名的大写形式，下面依次是 `src`（带折叠箭头）、`Cargo.toml`、`README.md`

#### Scenario: 全部折叠

- **WHEN** `src` 和 `src/git` 都已展开，用户点击「全部折叠」
- **THEN** 树中只剩根目录下的条目，所有文件夹都处于折叠状态

### Requirement: 条目的排列与排除

每个文件夹内 SHALL 先列文件夹、再列文件，各自按名称的自然顺序排列（不区分大小写，名称中的数字按数值比较，如 `file2` 排在 `file10` 前面）。以 `.` 开头的隐藏文件 SHALL 照常显示。以下条目 SHALL 永不显示（VS Code `files.exclude` 的默认值）：`.git`、`.svn`、`.hg`、`CVS`、`.DS_Store`、`Thumbs.db`。被 `.gitignore` 等规则忽略的条目 SHALL 照常显示，但名称使用较暗的颜色（VS Code 的 `gitDecoration.ignoredResourceForeground`，`#8C8C8C`）。

#### Scenario: 自然排序

- **WHEN** 文件夹中有 `b.rs`、`A.rs`、`file10.txt`、`file2.txt` 和文件夹 `z/`
- **THEN** 显示顺序为 `z`、`A.rs`、`b.rs`、`file2.txt`、`file10.txt`

#### Scenario: 被忽略的目录

- **WHEN** `.gitignore` 中有 `target/`
- **THEN** 根目录下的 `target` 以较暗的颜色显示，可以展开，展开后其中的条目同样较暗

#### Scenario: .git 不显示

- **WHEN** 用户查看仓库根目录
- **THEN** 列表中没有 `.git`

### Requirement: 按需加载

资源管理器 SHALL 只在文件夹被展开时才读取它的直接子条目，不预先遍历整棵目录树。展开一个含大量条目的文件夹（如 `node_modules`）时，界面 SHALL 保持可操作，列表 SHALL 只渲染可见的行。文件夹无法读取时（例如没有权限），SHALL 将其显示为空。

#### Scenario: 展开大目录

- **WHEN** 用户展开一个包含 5000 个子条目的文件夹
- **THEN** 子条目出现，滚动列表时保持流畅，期间界面没有卡住

#### Scenario: 打开仓库不遍历全树

- **WHEN** 用户打开一个 `target/` 下有几十万个文件的仓库
- **THEN** 资源管理器立即显示根目录内容，打开过程不会因为 `target/` 变慢

### Requirement: git 状态着色

资源管理器中的文件 SHALL 按 git 状态给名称着色，并在行的右侧显示状态字母，颜色和字母与源代码管理侧栏一致（M 修改、A 新增、D 删除、U 未跟踪、! 冲突等）。同一文件既有暂存又有未暂存改动时，SHALL 按未暂存的状态显示。文件夹 SHALL 取其子树中优先级最高的状态着色（冲突 > 未跟踪 > 删除 > 修改 > 新增），并在右侧显示一个同色圆点而不是字母。git 状态变化后，着色 SHALL 随之更新。

#### Scenario: 修改的文件

- **WHEN** `src/main.rs` 已修改未暂存，`src` 已展开
- **THEN** `main.rs` 的名称为黄色，右侧显示黄色的 `M`；`src` 的名称为黄色，右侧有一个黄色圆点

#### Scenario: 文件夹取最高优先级

- **WHEN** `src/` 下一个文件已修改，另一个文件未跟踪
- **THEN** `src` 按未跟踪的颜色显示

### Requirement: 单击、双击与键盘

在资源管理器中：
- 单击文件夹 SHALL 展开或折叠它。
- 单击文件 SHALL 以预览标签打开该文件（见 `file-editor` 的「预览标签」），键盘焦点留在资源管理器。
- 双击文件 SHALL 以普通标签打开它，并把键盘焦点移到编辑器。

资源管理器获得焦点时 SHALL 支持以下按键：↑ / ↓ 移动选中行；→ 展开选中的文件夹，已展开时移到第一个子条目；← 折叠选中的文件夹，已折叠或选中的是文件时移到父文件夹；空格以预览标签打开选中的文件；⌘↓ 以普通标签打开选中的文件，并聚焦编辑器。

#### Scenario: 单击文件

- **WHEN** 用户单击 `README.md`
- **THEN** 编辑区出现标题为斜体的 `README.md` 标签，`README.md` 行处于选中状态，键盘焦点仍在资源管理器

#### Scenario: 双击文件

- **WHEN** 用户双击 `Cargo.toml`
- **THEN** 编辑区出现标题为正常字体的 `Cargo.toml` 标签，光标在编辑器中闪烁，可以直接输入

#### Scenario: 键盘折叠

- **WHEN** 选中行是已展开文件夹 `src` 中的 `main.rs`，用户按 ←
- **THEN** 选中行移到 `src`；再按一次 ←，`src` 折叠

### Requirement: 定位当前文件

当前标签切换为某个文件标签或 diff 标签时，资源管理器 SHALL 展开该文件的所有上级文件夹，选中该文件所在的行，并把它滚动到可见范围内（VS Code 的 `explorer.autoReveal`）。被忽略的文件（位于被忽略的目录中）SHALL 不自动展开其上级文件夹。

#### Scenario: 从源代码管理打开后定位

- **WHEN** 用户在源代码管理中点击 `src/git/read.rs` 打开 diff，再切换到资源管理器
- **THEN** `src` 和 `src/git` 已展开，`read.rs` 处于选中状态且可见
