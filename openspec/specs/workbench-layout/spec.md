# workbench-layout Specification

## Purpose

按 VS Code 工作台的样式组织窗口：左侧源代码管理侧栏、右侧带标签页和面包屑的 diff 编辑区、底部状态栏，并使用 VS Code 内置的 Monokai Dimmed 深色配色（用户在 VS Code 里用的主题），让用户在熟悉的布局里完成查看和提交。

## Requirements

### Requirement: 整体布局

打开仓库后，窗口 SHALL 由四部分组成：活动栏、侧栏、右侧编辑区、底部贯通整个窗口宽度的状态栏。活动栏的位置由设置 `workbench.activityBar.location` 决定：在侧栏左侧、侧栏顶部、侧栏底部，或不显示（见 `explorer` 的「活动栏与侧栏视图」）。侧栏显示活动栏中选中的视图（资源管理器或源代码管理），默认为源代码管理。侧栏与编辑区之间 SHALL 可拖动调整宽度，侧栏默认宽度约 300 像素，切换视图时侧栏宽度保持不变。未打开仓库时，窗口 SHALL 只有编辑区，没有活动栏、侧栏和状态栏。

#### Scenario: 打开仓库后的布局

- **WHEN** 用户打开一个有改动的仓库，活动栏位置为默认值
- **THEN** 窗口最左侧是活动栏，其右是源代码管理侧栏，右侧是编辑区，底部是状态栏

#### Scenario: 调整侧栏宽度

- **WHEN** 用户拖动侧栏与编辑区之间的分隔线
- **THEN** 侧栏宽度随之变化，编辑区占据剩余宽度

#### Scenario: 切换视图不改变宽度

- **WHEN** 用户把侧栏拖到 400 像素宽后切换到资源管理器
- **THEN** 资源管理器侧栏仍是 400 像素宽

#### Scenario: 活动栏位置改变不改变侧栏宽度

- **WHEN** 侧栏为 400 像素宽，用户把活动栏位置从 `default` 改为 `top`
- **THEN** 侧栏仍是 400 像素宽，活动栏图标出现在侧栏顶部，编辑区因左侧少了 48 像素的活动栏而变宽

### Requirement: 源代码管理侧栏

侧栏自上而下 SHALL 包含：标题行（文字「SOURCE CONTROL」，右侧依次为「提交」✓、「刷新」、「…」更多操作按钮）；提交信息输入框；操作按钮（通常是右侧带下拉箭头的「✓ 提交」，按仓库状态也可能是「同步更改」「发布分支」「继续」，规则见 `source-control` 的「提交信息下方的操作按钮」）；文件分组列表。分组依次为「合并更改」「暂存的更改」「更改」，没有文件的组 SHALL 不显示；每个组标题 SHALL 可折叠，并在右侧显示文件数量徽标，鼠标悬停时显示组级操作按钮。

文件行 SHALL 显示：文件图标（统一的通用文件图标）、文件名、所在目录（较暗的颜色）、右侧的状态字母。状态字母与颜色 SHALL 采用 VS Code 的约定：M 修改、A 新增、D 删除、R 重命名、C 复制、U 未跟踪、! 冲突。鼠标悬停时 SHALL 在状态字母左侧显示该行的操作按钮，当前打开的文件行 SHALL 始终显示（对应 VS Code 的焦点行）；其余时候操作按钮 SHALL 不占位置，与 VS Code 的 `display: none` 一致。当前打开的文件行 SHALL 高亮。侧栏变窄时 SHALL 先截断目录、再截断文件名，末尾以省略号收尾；标题「SOURCE CONTROL」同样以省略号截断，右侧按钮始终完整显示。

#### Scenario: 文件行内容

- **WHEN** 「更改」组里有修改过的 `src/app/main.rs`
- **THEN** 该行显示 `main.rs`、较暗的 `src/app`，以及右侧黄色的 `M`

#### Scenario: 悬停显示操作

- **WHEN** 鼠标移到「更改」组的某个文件行上
- **THEN** 行右侧出现「打开文件」「放弃更改」「暂存更改」按钮

#### Scenario: 窄侧栏

- **WHEN** 侧栏拖到约 190 像素宽，「更改」组有 `src/parser/token.ts`，鼠标不在该行上且它不是打开的文件
- **THEN** 该行显示完整的 `token.ts` 和截断的目录，不为操作按钮留空；鼠标移上去后操作按钮出现，目录让出位置，文件名不够放时以省略号截断

#### Scenario: 空分组不显示

- **WHEN** 暂存区为空
- **THEN** 侧栏中不出现「暂存的更改」组

### Requirement: 编辑区

编辑区 SHALL 属于窗口，而不属于打开的仓库：无论是否打开了仓库都存在，切换仓库时保留不属于该仓库的标签（见 `open-repository`）。

**标签栏**：编辑区顶部 SHALL 是标签栏，按 `file-editor` 的「多标签」「标签的外观」规则，显示所有打开的文件标签、diff 标签和设置标签。标签栏右侧的按钮取决于当前标签：

- diff 标签：「打开文件」（见 `file-editor` 的「从源代码管理打开文件」；已删除的文件不显示）「上一处更改」「下一处更改」「切换并排/内联视图」。
- 设置标签：「打开设置(JSON)」。
- 文件标签：不显示按钮。

**面包屑**：标签栏下方 SHALL 是当前标签的路径面包屑，按目录层级显示文件路径；仓库外的文件从 `~` 开始显示。设置标签不显示面包屑。

**内容**：面包屑下方是当前标签的内容：

- diff 标签：该文件在其分组下的 diff。
- 文件标签：可编辑的文件内容。
- 设置标签：设置页面（见 `settings-editor`）。

**没有标签时**：已打开仓库时，编辑区 SHALL 显示空白背景及简短提示，不显示面包屑；未打开仓库时，SHALL 显示欢迎页内容（见 `open-repository` 的「选择文件夹的入口」），也不显示标签栏。

#### Scenario: 从「更改」组打开

- **WHEN** 用户点击「更改」组的 `.env.dev`
- **THEN** 出现标题为斜体的「.env.dev (工作树) M」标签，面包屑显示 `.env.dev`，下方是该文件暂存区与工作区的对照

#### Scenario: 切换内联视图

- **WHEN** 当前标签是 diff 标签，用户点击「切换并排/内联视图」
- **THEN** diff 在左右对照与单栏内联之间切换，当前文件保持不变

#### Scenario: 跳到下一处更改

- **WHEN** 当前标签是 diff 标签，用户点击「下一处更改」
- **THEN** diff 滚动到当前位置之后的下一处改动

#### Scenario: 文件标签不显示 diff 按钮

- **WHEN** 当前标签是 `a.rs` 文件标签
- **THEN** 标签栏右侧没有「上一处更改」「下一处更改」「切换并排/内联视图」按钮

#### Scenario: 设置标签的按钮

- **WHEN** 当前标签是设置标签
- **THEN** 标签栏右侧只有「打开设置(JSON)」按钮，下方没有面包屑

#### Scenario: 欢迎页在编辑区里

- **WHEN** 未打开仓库，也没有任何标签
- **THEN** 窗口只显示欢迎页内容，没有标签栏、活动栏和状态栏；用户按 ⌘, 后，出现只有「设置」一个标签的标签栏

### Requirement: 状态栏

状态栏 SHALL 位于窗口底部，左侧显示分支（分支图标 + 分支名）与同步入口（见 `source-control` 的「分支与同步状态」）。当前标签是文件标签时，右侧 SHALL 显示光标位置 `行 <行号>，列 <列号>`（见 `file-editor` 的「文件编辑」）。未打开仓库时，状态栏 SHALL 不显示分支、同步信息和光标位置。

#### Scenario: 状态栏内容

- **WHEN** 打开位于 `test` 分支、有未提交改动、落后上游 6 个提交的仓库
- **THEN** 状态栏左侧显示 `test*` 和 `6↓ 0↑`

#### Scenario: 光标位置

- **WHEN** 当前标签是文件标签，光标在第 3 行第 1 列
- **THEN** 状态栏右侧显示 `行 3，列 1`；切换到 diff 标签后不再显示

### Requirement: 在终端中打开

打开仓库后，用户按 ⌘J 或选择「文件 → 在终端中打开」时，系统 SHALL 用 Ghostty 打开仓库根目录，使新的终端会话以该目录为工作目录。应用 MUST NOT 内嵌终端。未打开仓库（欢迎页）时该操作 SHALL 不做任何事。Ghostty 无法打开时（例如未安装），系统 SHALL 显示「无法打开终端」错误通知并附上系统返回的原因。

#### Scenario: 按 ⌘J 打开终端

- **WHEN** 用户打开仓库 `~/code/app` 后按 ⌘J
- **THEN** Ghostty 出现新的窗口或标签，其中 shell 的当前目录是 `~/code/app`

#### Scenario: 欢迎页按 ⌘J

- **WHEN** 未打开任何仓库时用户按 ⌘J
- **THEN** 不打开终端，也不显示通知

#### Scenario: 没有安装 Ghostty

- **WHEN** 本机没有 Ghostty，用户在仓库中按 ⌘J
- **THEN** 窗口显示「无法打开终端」错误通知，内容包含系统给出的原因

### Requirement: Monokai Dimmed 配色

系统 SHALL 固定使用与 VS Code 内置主题 Monokai Dimmed 一致的深色配色，不跟随系统的浅色/深色设置。颜色 SHALL 取该主题的值，主题未设置的取 VS Code 暗色默认值。关键颜色：编辑区背景 `#1E1E1E`、侧栏背景 `#272727`、标签栏背景 `#282828`、未激活标签 `#404040`（当前标签与编辑区同色）、活动栏背景 `#353535`、状态栏背景 `#505050`、主要文字 `#CCCCCC`、主按钮 `#565656`、输入框背景 `#3C3C3C`、焦点边框 `#3655B5`、操作图标 `#C5C5C5`（`icon.foreground`）。

#### Scenario: 系统为浅色模式

- **WHEN** macOS 处于浅色外观，用户启动应用
- **THEN** 应用仍以 Monokai Dimmed 深色配色显示
