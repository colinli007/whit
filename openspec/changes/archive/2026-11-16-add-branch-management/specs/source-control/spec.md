## ADDED Requirements

### Requirement: 「…」更多操作菜单

侧栏标题的「…」菜单 SHALL 采用 VS Code 1.117 的结构，只包含本应用已实现的条目：

- 顶部：「拉取」「推送」（处于某个分支且该分支没有上游时为「发布分支」；分离头指针时仍为「推送」）「签出到...」「抓取」。
- 分隔线后依次为四个子菜单：
  - 「提交」：「提交」「提交(修改)」，变基进行中时追加「中止变基」。
  - 「更改」：「暂存所有更改」「取消暂存所有更改」「放弃所有更改」，对应分组没有文件时该项不可用。
  - 「拉取，推送」：「同步」「拉取」「推送」「抓取」。
  - 「分支」：「合并...」「变基分支…」，分隔线，「创建分支...」「从现有来源创建新的分支...」，分隔线，「重命名分支...」「删除分支...」「删除远程分支...」，分隔线，「发布分支...」；合并进行中时追加「中止合并」。

「创建分支...」等同于签出列表中输入为空时的「创建新分支...」，「从现有来源创建新的分支...」等同于「创建新分支依据...」。写操作进行中时，菜单里会改动仓库的条目 SHALL 不可用。处于分离头指针状态时，「重命名分支...」「发布分支...」SHALL 不可用；当前分支已有上游时「发布分支...」SHALL 不可用。

#### Scenario: 菜单结构

- **WHEN** 用户点击「…」
- **THEN** 依次看到「拉取」「推送」「签出到...」「抓取」，然后是「提交」「更改」「拉取，推送」「分支」四个子菜单

#### Scenario: 放弃所有更改

- **WHEN** 「更改」组里有 `a.rs` 和未跟踪的 `b.rs`，用户选择「…」→「更改」→「放弃所有更改」
- **THEN** 与点击「更改」组标题上的「放弃所有更改」按钮相同：先确认，确认后两者都被放弃

## MODIFIED Requirements

### Requirement: 提交信息下方的操作按钮

提交信息输入框下方的按钮 SHALL 按 VS Code 源代码管理「操作按钮」的规则，依次判断并显示仓库下一步需要的操作：

1. 合并或变基进行中：显示「✓ 继续」按钮（见 `branches` 的「合并或变基进行中」）。
2. 存在任何更改（合并、暂存或未暂存）：显示「提交」按钮（带下拉菜单）。
3. 当前处于某个分支、该分支没有上游：SHALL 显示次要样式的「发布分支」按钮（云上传图标），点击等同于发布分支。
4. 当前分支有上游并落后或领先上游：SHALL 显示次要样式的「同步更改」按钮，文字为「同步更改」后接「落后数↓」「领先数↑」，数为 0 的方向不显示（如 `同步更改 8↓`、`同步更改 8↓ 2↑`）；点击等同于执行同步（先确认再拉取并推送）。
5. 其余情况：显示「提交」按钮。

执行远程操作时，「发布分支」「同步更改」按钮的图标 SHALL 转动且按钮不可用；任何写操作进行中，按钮都 SHALL 不可用。

#### Scenario: 远程有新提交且工作区干净

- **WHEN** 没有任何更改，当前分支落后上游 8 个提交、不领先
- **THEN** 输入框下方显示「同步更改 8↓」按钮；确认同步后拉取完成，按钮恢复为「提交」

#### Scenario: 有更改时优先提交

- **WHEN** 「更改」组里有 `a.rs`，当前分支同时领先上游 1 个提交
- **THEN** 输入框下方仍显示「提交」按钮

#### Scenario: 新建的分支

- **WHEN** 用户刚创建并签出 `feature`，工作区干净
- **THEN** 输入框下方显示「发布分支」按钮；点击后 `feature` 被推送并设为上游，按钮恢复为「提交」

### Requirement: 拉取、推送、同步与获取

系统 SHALL 在侧栏标题的「…」菜单中提供「拉取」「推送」「同步」「抓取」（位置见「「…」更多操作菜单」）。拉取 SHALL 等同于在仓库执行 `git pull`（遵循用户自己的 git 配置，如 `pull.rebase`）；推送 SHALL 把当前分支推送到它的上游；同步 SHALL 先拉取、成功后再推送；抓取 SHALL 从默认远程获取最新引用但不修改工作区。当前分支没有上游时，「推送」与状态栏的同步入口 SHALL 变为「发布分支」，按 `branches` 的「发布分支」规则执行（只有一个远程时直接推送，多个远程时让用户选择，没有远程时提示）。

#### Scenario: 同步

- **WHEN** 本地领先上游 1 个提交、落后 2 个提交，用户执行同步
- **THEN** 系统先拉取 2 个提交，再推送本地提交，完成后状态栏显示 0↓ 0↑

#### Scenario: 发布分支

- **WHEN** 当前分支 `feature` 没有上游，仓库只有远程 `origin`，用户点击发布分支
- **THEN** `feature` 被推送到 `origin/feature` 并设为上游，状态栏改为显示同步计数

#### Scenario: 拉取产生冲突

- **WHEN** 拉取时发生合并冲突
- **THEN** 系统提示拉取失败并附 git 的输出，冲突文件出现在「合并更改」组

### Requirement: 分支与同步状态

系统 SHALL 在状态栏左侧显示当前分支名，工作区或暂存区有改动时在分支名后加 `*`；处于分离头指针状态时显示当前提交的短哈希。点击分支名 SHALL 打开「签出到」快速选择框（见 `branches` 的「签出到」）；写操作进行中时分支名不可点击。分支有上游时，SHALL 显示同步入口及「落后数↓ 领先数↑」（以本地已知的上游引用计算，不自动联网）；点击同步入口 SHALL 先确认「将从 <远程>/<分支> 拉取并推送提交」，确认后执行同步。分支没有上游时，同步入口 SHALL 显示为「发布分支」。处于分离头指针状态时（包括变基进行中），没有可同步或发布的分支，SHALL 不显示同步入口（与 VS Code 相同）。

#### Scenario: 显示同步计数

- **WHEN** 当前分支 `main` 领先 `origin/main` 2 个提交、落后 0 个
- **THEN** 状态栏显示 `main` 和 `0↓ 2↑`

#### Scenario: 有未提交改动

- **WHEN** 工作区有未提交的改动
- **THEN** 状态栏的分支名显示为 `main*`

#### Scenario: 点击分支名

- **WHEN** 用户点击状态栏的 `main`
- **THEN** 窗口顶部出现「选择要签出的分支或标记」快速选择框

#### Scenario: 分离头指针

- **WHEN** 用户签出已分离的提交 `05c648e`，或变基停在冲突上
- **THEN** 状态栏只显示 `05c648e`，不显示同步入口；「…」菜单顶部那项为「推送」
