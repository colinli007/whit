# 性能对比：打开项目后的空闲内存

[English](performance.md) | 简体中文

Whit、Zed、VS Code 各自用**默认配置**打开同一个项目，什么都不操作，比较内存占用。

## 结果

| 应用 | 内存（中位数） | 波动范围 | 进程数 | 相对 Whit |
|---|---|---|---|---|
| **Whit 0.1.0** | **79.4 MB** | 79.4–79.4 MB | 1 | 1× |
| **Zed 1.28.1** | **171.9 MB** | 171.9–172.0 MB | 2 | 2.2× |
| **VS Code 1.117.0** | **583.3 MB** | 568.3–604.5 MB | 9 | 7.3× |

## 测试条件

- **机器**：MacBook（Apple M4，16 GB 内存），macOS 15.8。
- **项目**：一个 React + Vite 前端项目，1813 个跟踪文件，连同 `node_modules` 约 2.7 GB；工作区没有改动。
- **默认配置**：每个应用都用一个全新的空配置目录，没有用户设置和第三方扩展，不恢复上次的会话（不会带出终端、AI 智能体等）。
  - Whit：`HOME` 指向空目录，不读已有的最近项目和设置。
  - VS Code：`--user-data-dir` 和 `--extensions-dir` 都指向空目录，只运行内置扩展。
  - Zed：`--user-data-dir` 指向空目录。
- **启动方式**：清空环境变量，只保留 `HOME`、`USER`、`SHELL`、`TMPDIR` 和系统默认 `PATH`，和在 Finder 里双击打开一样；命令行参数只有项目路径。
- **空闲状态**：三者都只打开了项目，没有打开任何文件，所以都没有启动语言服务。Whit 显示的是空的源代码管理面板。

## 测量方法

- **指标**：`phys_footprint`，即「活动监视器」的「内存」列，用 `footprint -p <pid>` 读取。它包含被压缩和换出到磁盘的内存，在内存紧张时比 RSS 更接近实际占用。
- **范围**：应用主进程及其全部子进程（整棵进程树）的合计。
- **采样**：三个应用依次单独测试，同一时刻只开一个。每个打开后先静置 90 秒，再每 10 秒采样一次，共 12 次，取中位数。测完结束整棵进程树，等 10 秒再测下一个。

## 重现

```sh
scripts/memory_bench.sh <项目路径>             # 测 Whit、Zed、VS Code
scripts/memory_bench.sh <项目路径> whit zed    # 只测其中几个
```

结果以 Markdown 输出到标准输出，进度输出到标准错误。应用默认从 `/Applications` 读取，可以用 `WHIT_APP`、`ZED_APP`、`VSCODE_APP` 指定；`SETTLE`、`SAMPLES`、`INTERVAL` 可以调整时间参数。运行前请先退出要测的应用：已在运行的实例可能接管项目、让新实例直接退出，这时脚本会报告启动失败，而不是给出一个数字。

## 注意

- 测试时系统交换区已用约 11.6 GB，内存压力较大。三者在相同条件下测得，可以互相比较，但绝对值可能和内存宽松时略有出入。
- 这是「刚打开项目」时的开销。用户自己装的扩展、恢复的会话、打开文件后启动的语言服务都会让 VS Code 和 Zed 明显上涨；Whit 打开大文件的 diff 后也会上涨。
- Whit 是 git 改动查看与提交工具，不是通用编辑器。这里比较的是打开同一个项目时的基础开销，不是同等功能下的对比。
