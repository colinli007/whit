## Purpose

让用户选定一个本地文件夹，应用据此找到它所属的 git 仓库，作为后续查看改动的对象；无法查看时给出明确原因。

## ADDED Requirements

### Requirement: 选择文件夹的入口

系统 SHALL 提供三种打开文件夹的方式：菜单项「打开文件夹…」（快捷键 cmd-O）、未打开任何文件夹时窗口中央的「打开文件夹」按钮、启动时的命令行参数（第一个位置参数作为文件夹路径）。系统 SHALL 只允许选择文件夹，不允许选择文件。

#### Scenario: 通过菜单打开

- **WHEN** 用户按 cmd-O 并在系统对话框里选中一个文件夹
- **THEN** 窗口切换为该文件夹所属仓库的改动视图

#### Scenario: 通过命令行参数打开

- **WHEN** 用户以 `diffview <路径>` 启动应用，且该路径是 git 仓库内的文件夹
- **THEN** 应用启动后直接显示该仓库的改动视图，不弹出选择对话框

#### Scenario: 未打开时的空状态

- **WHEN** 应用不带参数启动
- **THEN** 窗口显示「打开文件夹」按钮，点击后弹出文件夹选择对话框

#### Scenario: 取消选择

- **WHEN** 用户在文件夹选择对话框里点取消
- **THEN** 窗口保持原来的内容不变

### Requirement: 定位仓库根目录

系统 SHALL 以所选文件夹所属 git 仓库的工作区根目录作为查看对象；所选文件夹是仓库的子目录时，SHALL 展示整个仓库的改动，而不只是该子目录。窗口标题 SHALL 显示仓库根目录的文件夹名。

#### Scenario: 选中仓库子目录

- **WHEN** 用户选中仓库 `repo` 下的子目录 `repo/src`
- **THEN** 系统展示 `repo` 整个工作区的改动，窗口标题为 `repo`

### Requirement: 再次打开会替换当前仓库

在已打开一个仓库时再打开另一个文件夹，系统 SHALL 在同一窗口里替换为新仓库的内容，不新开窗口。

#### Scenario: 切换仓库

- **WHEN** 已打开仓库 A，用户再打开仓库 B
- **THEN** 同一窗口显示仓库 B 的改动，不再显示 A 的内容

### Requirement: 无法查看时的提示

当所选文件夹不在任何 git 仓库内、本机找不到 `git` 命令，或 git 命令执行失败时，系统 SHALL 在窗口中显示说明原因的提示（git 失败时包含 git 输出的错误信息），并保留重新打开文件夹的入口。系统 MUST NOT 因此崩溃。

#### Scenario: 不是 git 仓库

- **WHEN** 用户选中一个不在任何 git 仓库内的文件夹
- **THEN** 窗口提示「该文件夹不是 git 仓库」并显示「打开文件夹」按钮

#### Scenario: 找不到 git

- **WHEN** 本机 PATH 中没有 `git` 可执行文件，用户打开一个文件夹
- **THEN** 窗口提示需要安装 git，应用不崩溃
