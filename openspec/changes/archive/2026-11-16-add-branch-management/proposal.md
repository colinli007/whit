## Why

用户的目标是让 diffview 左侧的源代码管理和 VS Code 1.117 的功能一样。目前 diffview 只能看改动、暂存、提交、拉取推送，切分支、建分支、合并这些日常操作还得回 VS Code 或终端。VS Code 里这些操作共用同一个界面：窗口顶部居中的「快速选择框 / 输入框」（如点状态栏分支后出现的「选择要签出的分支或标记」）。diffview 还没有这个组件，所以这一期先把它做出来，再在它上面做分支的全部操作。用户选了「分支全套」这一档范围。

这改变了项目边界：`openspec/config.yaml` 原来把「分支创建与切换」列为不做。这次是用户明确提出的，本变更会同步改写 config 里的边界描述。

## What Changes

- **快速选择框 / 输入框**（VS Code 的 Quick Input）：窗口顶部居中浮出，带输入框和可过滤列表；支持分组（分组名显示在该组第一行右侧）、每行图标 + 名称 + 灰色说明 + 第二行详情、键盘上下选择、回车确认、Esc 或点外面关闭；输入框模式有提示文字和实时校验信息。
- **签出到…**：点击状态栏的分支名，或「…」菜单的「签出到...」，打开「选择要签出的分支或标记」。列表顶部是「创建新分支...」「创建新分支依据...」「签出已分离…」，下面是「分支」「远程分支」「标记」三组，按最近提交时间排序。本地分支显示「落后↓ 领先↑ • 时间」，远程分支和标记显示时间，第二行显示「作者 • 短哈希 • 提交标题」。选远程分支时，如果已有本地分支跟踪它就签出该本地分支，否则新建一个跟踪它的本地分支。
- **工作区有改动导致签出失败时**，按 VS Code 的方式询问「签出会覆盖本地更改。」，提供「储藏并签出」「迁移更改」（储藏 → 签出 → 弹出储藏）「强制签出」（放弃全部更改后签出）三个选项。
- **创建分支**：「创建新分支...」直接用已输入的文字作为分支名初值，「创建新分支依据...」先选起点（HEAD、分支、远程分支、标记），再输入分支名。空格自动替换成 `-` 并提示「新分支将为“x”」，重名时提示已存在。创建后自动签出新分支。
- **其它分支操作**：重命名分支、删除分支（分支没有完全合并时再问一次是否仍要删除）、删除远程分支、合并（选分支或标记）、变基（选分支，当前分支的上游排第一位并标注「(upstream)」）、发布分支（有多个远程时让用户选择推送到哪个）。
- **合并 / 变基进行中**：冲突文件照常出现在「合并更改」组。提交按钮变成「继续」：冲突解决并暂存后，合并时用 git 生成的合并提交信息完成提交，变基时执行 `rebase --continue`。变基进行中「提交」子菜单出现「中止变基」，合并进行中「分支」子菜单出现「中止合并」。
- **「…」菜单改成 VS Code 的结构**：顶部是「拉取」「推送」「签出到...」「抓取」；下面是「提交」「更改」「拉取，推送」「分支」四个子菜单，只放本期已实现的条目。
- **提交框下方的操作按钮**：在已有的「提交 / 同步更改」两种之外，新增「发布分支」（没有改动、分支还没有上游时显示）和「继续」（合并或变基进行中时显示）。

## 不做的事

- 「…」菜单里的「远程」「储藏」「标记」「工作树」子菜单，以及储藏列表的查看、应用、删除。储藏只作为「储藏并签出 / 迁移更改」的内部步骤使用。这些放下一期。
- 拉取、推送的变体（拉取(变基)、拉取自...、推送到...、强制推送、获取（删除）、从所有远程存储库中拉取、同步(变基)），以及提交的变体（全部提交、提交已暂存文件、撤消上次提交、署名、不验证）。放下一期。
- 克隆、连接远程仓库、发布到 GitHub（VS Code 在没有远程时会提供「发布到 GitHub」；diffview 只提示仓库没有远程）。
- 冲突解决界面：「采用当前 / 传入更改」、三方合并编辑器、交互式变基（`rebase -i`）。
- 「签出前先拉取」（`git.pullBeforeCheckout`）、随机分支名、分支前缀、受保护分支等 VS Code 设置项。diffview 没有设置界面，一律按 VS Code 默认值处理。
- 命令面板（⇧⌘P）。快速选择框只由菜单、状态栏和按钮打开。
- 源代码管理图（Graph）和提交历史（仍按原计划放在后续的「提交历史与分支对比」期）。

## Capabilities

### New Capabilities

- `quick-input`：窗口顶部居中的快速选择框与输入框，包括它的位置、列表行样式、分组、过滤、键盘与鼠标交互、输入校验和关闭规则。
- `branches`：签出到（含签出已分离、远程分支建立跟踪、工作区有改动时的三种处理）、创建分支、从指定起点创建分支、重命名、删除本地 / 远程分支、合并、变基、发布分支（选远程），以及合并 / 变基进行中的继续与中止。

### Modified Capabilities

- `source-control`：「…」菜单改为 VS Code 的分组子菜单结构，新增「签出到...」；提交框下方的操作按钮新增「发布分支」和「继续」两种状态；点击状态栏分支名打开「签出到」；发布分支在有多个远程时改为让用户选择（取代「多个远程且没有 origin 时报错」）。
- `workbench-layout`：侧栏中提交信息下方的按钮不再固定为「✓ 提交」，改为引用 `source-control` 的操作按钮规则。

## Impact

- 代码：
  - 新增快速选择框组件：建在 vendor 的 gpui-component `command` 命令面板之上，外层自己负责定位和分组标签。
  - `src/git/`：新增读取引用列表（`for-each-ref`）、合并 / 变基状态（`.git/MERGE_HEAD`、`rebase-merge`、`rebase-apply`）、合并提交信息（`MERGE_MSG`），以及签出、建分支、改名、删除、合并、变基、储藏 / 弹出等写命令。
  - `src/workbench/`：新增分支操作的流程编排；修改「…」菜单、操作按钮和状态栏。
  - `src/main.rs`：新增对应的动作。
- 依赖：新增直接依赖 `futures-channel`（0.3.34，最新版，原本就是间接依赖），用它的一次性通道把快速选择框的选择结果交回等待中的流程；gpui 本身没有导出可用的通道类型。
- 行为风险：签出、强制签出、合并、变基、删除分支都会改动用户仓库。强制签出会丢掉未提交的改动，删除未合并的分支会丢掉提交，这两种都要经过 VS Code 同款的确认框。
- 文档：`openspec/config.yaml` 的项目边界、README 的功能说明、项目记忆需要同步更新。
