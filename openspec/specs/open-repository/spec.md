# open-repository Specification

## Purpose

让用户选定一个本地文件夹，应用据此找到它所属的 git 仓库，作为后续查看改动的对象；无法查看时给出明确原因。

## Requirements

### Requirement: 选择文件夹的入口

系统 SHALL 提供四种打开文件夹的方式：菜单项「打开文件夹…」（快捷键 cmd-O）、欢迎页上的「打开…」、欢迎页「最近」列表中的项目、启动时的命令行参数（第一个位置参数作为文件夹路径）。系统 SHALL 只允许通过对话框选择文件夹，不允许选择文件。欢迎页是未打开仓库且没有标签时编辑区显示的内容（见 `workbench-layout` 的「编辑区」）；未打开仓库时打开的标签（如设置标签）会盖住它，关闭这些标签后欢迎页重新出现。

#### Scenario: 通过菜单打开

- **WHEN** 用户按 cmd-O 并在系统对话框里选中一个文件夹
- **THEN** 窗口切换为该文件夹所属仓库的工作台视图

#### Scenario: 通过命令行参数打开

- **WHEN** 用户以 `whit <路径>` 启动应用，且该路径是 git 仓库内的文件夹
- **THEN** 应用启动后直接显示该仓库的工作台视图，不显示欢迎页、不弹出选择对话框

#### Scenario: 未打开时的空状态

- **WHEN** 应用不带参数启动
- **THEN** 窗口显示欢迎页：左侧是应用名和「启动」区（含「打开…」），右侧是「最近」项目列表

#### Scenario: 取消选择

- **WHEN** 用户在文件夹选择对话框里点取消
- **THEN** 窗口保持原来的内容不变

#### Scenario: 打开设置后再打开仓库

- **WHEN** 未打开仓库，用户先按 ⌘, 打开设置，再按 cmd-O 选中一个仓库
- **THEN** 窗口切换为该仓库的工作台视图，标签栏中仍有「设置」标签

### Requirement: 定位仓库根目录

系统 SHALL 以所选文件夹所属 git 仓库的工作区根目录作为查看对象；所选文件夹是仓库的子目录时，SHALL 展示整个仓库的改动，而不只是该子目录。窗口标题 SHALL 显示仓库根目录的文件夹名。

#### Scenario: 选中仓库子目录

- **WHEN** 用户选中仓库 `repo` 下的子目录 `repo/src`
- **THEN** 系统展示 `repo` 整个工作区的改动，窗口标题为 `repo`

### Requirement: 再次打开会替换当前仓库

在已打开一个仓库时再打开另一个文件夹，系统 SHALL 在同一窗口里替换为新仓库的内容，不新开窗口。当前仓库有未保存修改的文件标签时，SHALL 先按 `file-editor` 的「关闭前询问保存」询问；用户选择「取消」时，SHALL 保持当前仓库不变。替换后，原仓库的 diff 标签和仓库内文件的文件标签 SHALL 关闭；设置标签和仓库外文件的文件标签（如 `settings.json`）SHALL 保留，未保存修改也一并保留，不参与这次询问。

#### Scenario: 切换仓库

- **WHEN** 已打开仓库 A，用户再打开仓库 B
- **THEN** 同一窗口显示仓库 B 的改动，不再显示 A 的内容和 A 的标签

#### Scenario: 有未保存修改时取消切换

- **WHEN** 仓库 A 中的 `a.rs` 有未保存修改，用户打开仓库 B，并在保存询问中选择「取消」
- **THEN** 窗口仍显示仓库 A，`a.rs` 的修改仍在

#### Scenario: 设置标签跨仓库保留

- **WHEN** 已打开仓库 A，标签栏有 `a.rs` 和「设置」，用户再打开仓库 B
- **THEN** `a.rs` 标签关闭，「设置」标签保留

### Requirement: 无法查看时的提示

当所选文件夹不在任何 git 仓库内、本机找不到 `git` 命令，或 git 命令执行失败时，系统 SHALL 在欢迎页上显示说明原因的提示（git 失败时包含 git 输出的错误信息），并保留「打开…」和最近项目入口。系统 MUST NOT 因此崩溃。

#### Scenario: 不是 git 仓库

- **WHEN** 用户选中一个不在任何 git 仓库内的文件夹
- **THEN** 欢迎页提示「该文件夹不是 git 仓库」，「打开…」和最近列表仍可使用

#### Scenario: 找不到 git

- **WHEN** 本机 PATH 中没有 `git` 可执行文件，用户打开一个文件夹
- **THEN** 欢迎页提示需要安装 git，应用不崩溃

### Requirement: 最近打开的项目

每次成功打开仓库后，系统 SHALL 把仓库根目录记入最近项目列表：已存在则移到最前，列表最多保留 50 项，按最近打开时间倒序。列表 SHALL 持久保存，应用重启后仍在。欢迎页「最近」区 SHALL 每行显示仓库文件夹名（链接样式）和上级目录路径（用户主目录替换为 `~`），默认显示前 10 项，超过时末尾显示「更多…」，点击后展开全部。点击某一项 SHALL 打开该仓库。该路径已不存在或已不是 git 仓库时，SHALL 提示原因并询问是否从列表移除。列表为空时，「最近」区 SHALL 显示「没有最近打开的文件夹」。

#### Scenario: 记录并显示

- **WHEN** 用户打开过 `~/Desktop/xwm/zed-lite` 后重启应用
- **THEN** 欢迎页「最近」区第一行显示 `zed-lite` 和 `~/Desktop/xwm`

#### Scenario: 再次打开移到最前

- **WHEN** 最近列表依次为 A、B、C，用户打开 C
- **THEN** 列表变为 C、A、B

#### Scenario: 展开更多

- **WHEN** 最近列表有 15 项
- **THEN** 欢迎页只显示前 10 项和「更多…」；点击「更多…」后显示全部 15 项

#### Scenario: 路径已不存在

- **WHEN** 用户点击的最近项目文件夹已被删除
- **THEN** 系统提示该文件夹不存在，并询问是否从最近列表中移除；选择移除后该项从列表消失

### Requirement: 关闭文件夹

系统 SHALL 提供菜单项「文件 → 关闭文件夹」。执行后，窗口标题恢复为应用名，未完成的读取任务被丢弃，该仓库的 diff 标签和仓库内文件的文件标签关闭；设置标签和仓库外文件的文件标签保留。没有剩余标签时编辑区显示欢迎页，否则显示剩余的标签，关掉它们后显示欢迎页。仓库内有未保存修改的文件标签时，SHALL 先按 `file-editor` 的「关闭前询问保存」询问；用户选择「取消」时，SHALL 保持文件夹打开。未打开文件夹时，该菜单项 SHALL 不起作用。

#### Scenario: 关闭后回到欢迎页

- **WHEN** 已打开仓库 A，用户选择「关闭文件夹」
- **THEN** 窗口显示欢迎页，最近列表的第一项是 A

#### Scenario: 有未保存修改时关闭

- **WHEN** `a.rs` 有未保存修改，用户选择「关闭文件夹」，并在保存询问中选择「保存」
- **THEN** `a.rs` 被写回磁盘，然后窗口回到欢迎页

#### Scenario: 关闭文件夹时设置标签保留

- **WHEN** 已打开仓库 A，标签栏有 `a.rs` 和「设置」，用户选择「关闭文件夹」
- **THEN** 窗口没有活动栏、侧栏和状态栏，标签栏只剩「设置」；关闭它后显示欢迎页
